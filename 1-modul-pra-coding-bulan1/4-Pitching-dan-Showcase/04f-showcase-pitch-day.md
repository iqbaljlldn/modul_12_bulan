## 3. Aturan Main di Atas Panggung

1. **Disiplin Waktu 7 Menit:** Pada menit ke-6, mentor akan mengangkat penanda kuning (1 menit tersisa). Pada menit ke-7 pas, penanda merah diangkat dan presentasi dihentikan.
2. **Keterlibatan Penuh Anggota:** Ketiga anggota squad wajib berbicara di panggung dan menjawab pertanyaan panelis secara bergantian sesuai pembagian perannya.
3. **Etika Audiens:** Seluruh peserta yang sedang tidak tampil wajib menyimak dengan seksama, menutup laptop, dan mengisi lembar apresiasi peer-feedback.

## 4. Evaluasi 8 Checkpoint Kapabilitas Pra-Coding

Di akhir Showcase, mentor mengevaluasi kesiapan setiap murid menggunakan **Checklist 8 Kapabilitas Inti** dengan 3 status: **Siap**, **Hampir Siap**, atau **Perlu Pendampingan**. Tidak ada vonis nilai angka atau pemotongan skor yang menghukum.

| # | Checkpoint Kapabilitas | Bukti Pengujian Nyata | Status Kesiapan | Catatan Masukan Mentor |
|---|---|---|---|---|
| **1** | **Computational Thinking** | Mampu memecah masalah bisnis runtut tanpa ambigu (Dekomposisi, Pola, Abstraksi, Algoritma/Pseudocode baku). | [ ] Siap<br>[ ] Hampir Siap<br>[ ] Perlu Pendampingan | |
| **2** | **Alur Flowchart Baku** | Menggambar alur sistem dengan simbol standar baku, percabangan jelas (*Ya/Tidak*), dan alur pemesanan WhatsApp lengkap. | [ ] Siap<br>[ ] Hampir Siap<br>[ ] Perlu Pendampingan | |
| **3** | **Pemodelan Data ERD Dasar** | Membedakan entitas, atribut unik (*PK*), relasi 1:N, dan entitas penghubung `ItemPesanan` untuk relasi N:N. | [ ] Siap<br>[ ] Hampir Siap<br>[ ] Perlu Pendampingan | |
| **4** | **Wireframe Mobile-First** | Merancang tata letak antarmuka sederhana (Katalog, Detail, Dashboard) yang ramah bagi pengguna awam UMKM. | [ ] Siap<br>[ ] Hampir Siap<br>[ ] Perlu Pendampingan | |
| **5** | **Value Proposition & Riset Pengguna** | Menjelaskan nilai solusi berbasis data wawancara UMKM nyata dan persona yang membumi. | [ ] Siap<br>[ ] Hampir Siap<br>[ ] Perlu Pendampingan | |
| **6** | **AI Literacy & Etika** | Memakai AI sebagai sparring partner terstruktur (formula R-C-I-C-O), memvalidasi fakta, dan patuh Piagam Etika Tribe. | [ ] Siap<br>[ ] Hampir Siap<br>[ ] Perlu Pendampingan | |
| **7** | **Komunikasi & Pitching 7 Menit** | Menyampaikan narasi produk percaya diri dengan struktur Problem → Solusi → Bukti/Demo → Dampak → Roadmap. | [ ] Siap<br>[ ] Hampir Siap<br>[ ] Perlu Pendampingan | |
| **8** | **Kolaborasi Git & GitHub** | Mengelola seluruh artefak dan latihan kode ke repositori GitHub tim melalui alur branch dan Pull Request yang rapi. | [ ] Siap<br>[ ] Hampir Siap<br>[ ] Perlu Pendampingan | |

> *Catatan Pendampingan:* Murid yang mendapatkan status **Perlu Pendampingan** pada salah satu checkpoint akan mengikuti sesi klinik santai bersama mentor pada hari Senin pagi sebelum coding React dimulai, agar tidak ada yang tertinggal saat memasuki Bulan 2.

## 5. Penghargaan Apresiasi Squad (*Tribe Awards*)

Di akhir acara, mentor mengumumkan penghargaan apresiasi tim:
- 🏆 **The Best Overall Pitch:** Squad dengan narasi paling memukau dan penguasaan panggung paling percaya diri.

## 7. Tugas Mandiri (Individual): Refleksi Akbar Akhir Bulan 1

- **Sifat:** Individu (dikerjakan sendiri setelah acara Showcase selesai)
- **Target Waktu:** 25 menit
- **Nama File:** Simpan di folder pribadimu dalam repo squad dengan nama `tugas_04f.md`

### Instruksi:
Tuliskan refleksi penutup Bulan 1 yang memuat:
1. Perbandingan dirimu: Apa perbedaan terbesar cara berpikirmu sebelum masuk Bulan 1 vs sekarang setelah 4 minggu belajar?
2. Dari 8 Checkpoint Kapabilitas di atas, kapabilitas mana yang paling membuatmu bangga dan kapabilitas mana yang ingin terus kamu asah?
3. Pesan dan kesiapan mentalmu menyambut hari pertama coding React & TypeScript di Bulan 2 hari Senin depan!

### Contoh Hasil yang Diharapkan:
```markdown
# Tugas Mandiri 04f — Refleksi Akbar Akhir Bulan 1
Nama: [Nama Kamu]
Squad: Squad 3

## 1. Perubahan Pola Pikir Saya:
Dulu saya mengira menjadi programmer itu hanya soal mengetik sintaks secepat mungkin. Sekarang saya paham bahwa bagian tersulit sekaligus paling penting adalah memahami masalah pedagang di lapangan, merancang alur flowchart yang tidak buntu, dan menata hubungan tabel data sebelum menulis kode.

## 2. Evaluasi 8 Checkpoint Saya:
- Paling Membanggakan: Kemampuan menggambar ERD dan Flowchart alur pemesanan WhatsApp. Saat ditanya panelis tadi, saya bisa menjelaskan fungsi tabel ItemPesanan dengan lancar.
- Ingin Terus Diasah: Kecepatan memecah tugas menjadi User Story dan Acceptance Criteria yang detail.

## 3. Kesiapan Menuju Bulan 2:
Saya sangat bersemangat! Di latihan mandiri Minggu 2 dan 3 kemarin, saya sudah mencoba fungsi JS dan kartu HTML/CSS. Sekarang saya sudah tidak sabar membuka VS Code hari Senin besok untuk mulai membangun komponen React pertama saya bersama tim.
```
